# 제공사 문의 초안 — 미전송

## 카카오

안녕하세요. 사용자에게서 네이버지도/카카오맵 장소 공유 텍스트와 URL을 받아 장소 후보를 확인하고, 선택한 장소를 개인 데이트 계획에 연결하는 앱을 개발하고 있습니다. 기존 대학가이드 앱의 Local API를 이 서비스에 이용하는 구성을 검토 중입니다. 다음 조건이 허용되는지 확인 부탁드립니다.

1. 같은 개발자 계정의 기존 앱 키·무료 쿼터를 별도 서비스인 Duri Date 백엔드에 사용하는 것이 가능한지, 앱 정보 변경 또는 별도 앱 등록이 필요한지요?
2. 검색 후보의 ID·이름·상세 URL만 서버에 최대 15분 캐시하고 사용자 선택 후 최대 7일 보관할 수 있나요? 자동 확정과 사용자 명시 선택은 각각 어떤 조건을 적용받나요?
3. 주소·좌표는 요청 처리 메모리에서만 사용하고 응답·DB·로그에 저장하지 않습니다. 이 값으로 계산한 앱 내부 시·도/시군구 ID만 7일 보관하고 지역 필터에 사용하는 것은 가능한가요?
4. 장소 ID·이름·URL 중 허용되지 않는 항목, 삭제·갱신 주기와 필수 출처 표기를 안내 부탁드립니다. 지도 화면 없이 후보 목록과 카카오맵 링크만 표시하는 경우의 조건도 알고 싶습니다.
5. 네이버 공유 원문을 카카오 검색으로 보완하거나, 다른 지도 결과와 같은 목록에서 출처를 구별해 표시하는 경우의 제한이 있나요?

현재 운영 장소/지역 저장 플래그는 꺼져 있습니다. 공개 장소 연결·지역 비교 검사에서는 API 결과를 메모리에서 처리하고 통과 여부와 지연만 기록했습니다. 전체 API 응답, 주소, 좌표, 전화, 카테고리, 이미지는 보관하지 않습니다.

참고한 답변의 문맥이 달라 본 서비스 조건의 확인을 요청합니다:
- https://devtalk.kakao.com/t/api-id-place-url/151265
- https://devtalk.kakao.com/t/local-api/151645

## NAVER API HUB

안녕하세요. NAVER API HUB 지역 검색을 통해 사용자가 공유한 장소의 후보를 검색하고 개인 데이트 계획의 장소를 확인하는 앱을 개발 중입니다.

1. 검색 결과 이름·상세 URL을 후보 선택용으로 최대 15분 캐시하고 명시 선택 후 최대 7일 보관하는 것이 허용되나요? 자동 판별 확정에 다른 조건이 있나요?
2. 주소는 일회성 메모리 처리에만 사용하고 앱 내부 시·도/시군구 ID를 계산하려 합니다. 파생 ID의 보관과 필터 활용 허용 여부를 알려주세요.
3. 저장 가능한 필드별 캐시 기한, 삭제·갱신 및 출처 표기 조건을 확인하고 싶습니다. 외부 지도와 함께 결과를 표시하는 경우 제한도 부탁드립니다.
4. 신규 API HUB 계정의 무료 한도, 초과 호출 차단 설정, 요금과 호출 제한을 확인하고 싶습니다.
5. 지역 검색 결과에 장기 재조회용 장소 식별자가 제공되는지, 없으면 동일 장소 재조회에 권장하는 공식 방법이 있는지요?

전체 응답과 주소·좌표·전화·카테고리·이미지는 DB·로그에 저장하지 않으며, 확인 전 장소/지역 저장 기능은 비활성 상태입니다.

## 답변 반영

허용 여부와 조건, 문의 URL/답변 일자, 서비스/앱 식별, 보관 기한을 provider-policy.md에 기록합니다. 현재 후보 15분·작업 7일보다 짧은 기한을 요구하면 코드를 먼저 수정합니다. 답변 없이 승인 플래그만 켜지 않습니다. 이 문서는 초안이며 실제 문의는 전송하지 않았습니다.
