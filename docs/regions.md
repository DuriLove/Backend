# 지역 매핑 규칙

프론트 HEAD `fc51355dc9c3eb087683eef610ca7b3dcb0f0f43`의 regionData.ts와 regionCatalog.ts를 Backend에 복사했습니다. Frontend 파일은 수정하지 않았습니다. 17개 시·도, 228개 시군구의 앱 고정 ID를 사용합니다. 행정구역 최신성 검증은 별도이며 현재 앱과의 호환성이 우선입니다.

GET /api/v1/region-catalog 및 region-manifest.json의 version은 목록 내용의 SHA-256에서 계산합니다. 접수의 버전이 다르면 409 CATALOG_VERSION_MISMATCH입니다. 프론트가 연동할 때 이 version을 전달해야 합니다.

1. 주소 첫 토큰을 시·도의 정식명·shortName·명시적 구 명칭 별칭으로 찾습니다.
2. 두 번째 토큰은 해당 시·도의 자식 시군구 이름과 정확히 일치해야 합니다.
3. 성남시 분당구, 고양시 일산동구 등은 명시적인 시·구 대응표를 거쳐 앱 카탈로그의 성남시·고양시로 연결합니다. 미지 구는 partial입니다.
4. 정확히 아는 상위 지역만 partial로 반환하고 나머지는 null입니다. 알 수 없는 시·도는 unmapped입니다. 새 결과에는 selectable=true인 ID만 사용합니다.
5. 세종처럼 하위 시군구가 없는 카탈로그는 provinceId만 있는 partial입니다. 홍대·성수 등 dateAreaId는 항상 null입니다.
6. 자동 확정할 카카오 장소의 원래 WGS84 좌표가 있으면 법정동 기반 시·도/시군구와 주소 결과를 비교합니다. 충돌 시 후보 확인으로 낮춥니다. 주소가 없으면 좌표 결과로 보완합니다. 지역 응답의 대표 좌표로 원래 좌표를 덮어쓰지 않습니다.
7. 사용자 후보 선택의 지역은 후보 생성 시 주소로 확인한 수준을 사용합니다. 주소/좌표 충돌 후보는 unmapped를 유지합니다. 후보의 상세 주소·좌표는 저장하지 않습니다.
8. 기존 데이트의 수동 지역을 작업 결과로 바꾸지 않습니다. 기존 비활성·미지 저장 ID는 유지할 수 있지만 새 수동 지역 선택은 활성 카탈로그 ID만 허용합니다.

반경 검색, GPS 추정, 날짜 희망 지역 자동 변경, 최신 국가 행정코드 동기화는 구현 범위에 포함하지 않습니다.
