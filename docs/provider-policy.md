# 제공사 지원 범위와 저장 정책

2026-10-02 구현 기준입니다. 공식 API 호출 형식을 확인했으며, 특정 앱에 대한 데이터 저장 허가를 취득했다는 의미는 아닙니다.

| 항목 | 네이버 | 카카오 |
|---|---|---|
| 검색 | 공식 지역 검색 API, 최대 5개 | 공식 Local 키워드 검색, 최대 15개 |
| 공유 ID 단건 조회 | 제공 기능으로 가정하지 않음 | 제공 기능으로 가정하지 않음 |
| providerPlaceId | 검색 결과에 ID가 없으므로 null | Local 응답의 id |
| 좌표 | mapx/mapy를 임의로 도 단위로 해석하지 않고 주소 사용 | x=경도, y=위도 범위 검사; 자동 확정 시 좌표 지역과 주소 지역 대조 |
| 자동 확정 | 정확한 장소명+전체 주소의 유일 일치 | 장소명과 동일 출처 ID의 일치 또는 이름+주소 일치; 제공된 주소와 충돌하면 확정 금지 |
| 단축 링크 | naver.me를 안전하게 확장 | kko.to를 안전하게 확장 |
| URL만 있고 이름 없음 | 이름 추가 입력 필요 | 이름 추가 입력 필요 |

공식 근거:
- https://developers.naver.com/docs/serviceapi/search/local/local.md
- https://developers.kakao.com/docs/ko/local/dev-guide

검색 첫 결과, 이름 일부, 지점명이 생략된 검색은 자동 확정 근거로 사용하지 않습니다. URL ID가 있는 카카오 결과는 다른 ID를 같은 장소로 취급하지 않습니다. 서울 중구와 부산 중구를 합치지 않습니다. 제공사 ID가 없는 네이버 결과를 임의 ID로 만들어 다른 제공사 결과와 병합하지 않습니다.

지원되는 직접 링크는 네이버 `/place/{id}`, `/entry/place/{id}`, `/restaurant/{id}`와 카카오 `place.map.kakao.com/{id}`, `/link/map/{id}`, `?itemId={id}`입니다. 검색·목록·길찾기, 다중 URL, 불명확한 최종 URL, 인스타그램 장소 추출은 지원하지 않습니다. 실제 앱별 공유 포맷은 실샘플로 추가 검증해야 합니다. HTTP 지도 링크는 알려진 호스트에 한해 HTTPS로 정규화하고, 실제 네트워크는 HTTPS만 사용합니다.

## 필드별 저장

| 필드 | 기본 동작 | 승인 후 |
|---|---|---|
| 사용자 공유 원문·URL | 인증된 소유자의 작업으로 7일 | DELETE로 즉시 삭제 가능 |
| 제공사 ID·이름·URL | 공급자 호출과 저장 차단 | PLACE_STORAGE_APPROVED 설정 시 후보 15분, 확정 결과 최대 7일 |
| 원문 API 응답 | 저장·로그 출력 안 함 | 변경 없음 |
| 외부 주소·좌표 | 처리 메모리에서만 사용, DB·로그·응답에 기록하지 않음 | 변경 없음 |
| 전화·카테고리·이미지 | 장소 분석에서 수집·저장하지 않음 | 변경 없음 |
| 파생 지역 ID | policy_blocked, ID는 null | REGION_STORAGE_APPROVED 설정 시 장소와 동일 보관 기간 |
| 링크 미리보기 제목·이미지 URL | 허용 호스트에서 한정된 응답을 읽어 반환 | 서버 DB에 자동 저장하지 않음 |

PLACE_STORAGE_APPROVED는 자동 검색 결과의 후보 캐시와 확정 결과 보관을 모두 허용받았을 때만 켭니다. REGION_STORAGE_APPROVED는 파생 앱 ID의 보관·필터 활용을 확인한 뒤 별도로 켭니다. 제공사 출처는 `place.provider`, 링크는 `place.url`로 제공됩니다. 프론트에서 필요한 로고·출처 표기, 다른 지도와 결합 가능 여부는 제품 이용 조건 확인이 필요합니다. 주소가 없는 동명 후보는 제공사 링크를 직접 확인하거나 더 구체적인 이름·주소를 입력하도록 해야 합니다.

실제 제공사 계정의 권한·한도·비용·캐시 허용 및 삭제 조건은 미확인입니다. 위 보관 기간이 자동으로 약관에 적합하다고 간주하지 않습니다. 해당 조건 확인 전 기본 차단을 유지하세요.

## 안전한 외부 호출

호스트 allowlist, scheme·포트·userinfo 제한, DNS 응답의 사설/예약 IP 검사, 검증한 IP에 고정한 연결, 리다이렉트 매 단계 재검증, 최대 4회 리다이렉트, 전체 8초 제한, 수신 중 250KB 제한을 적용합니다. 인증 키가 포함된 공식 API는 리다이렉트를 허용하지 않습니다. 사용자별 분당 120회, 로그인/회원가입 IP별 분당 20회, 제공사별 분당 60회·24시간 창 1,000회 제한을 DB에 기록합니다.

## 후속 조사 갱신

2026-10-03 조사에서 카카오 공식 답변 간 저장 범위 차이와 네이버 신규 API HUB 이관을 확인했습니다. 최신 근거와 구현 프로파일은 [provider-investigation.md](provider-investigation.md)를 우선 참조하세요. 새 네이버 앱은 API HUB가 기본이고, 기존 Developers API는 NAVER_API_MODE=legacy를 명시해야 합니다.

네이버 선택 장소 링크 `/p/search/<검색어>/place/<ID>`도 지원합니다. ID가 없는 일반 검색, 경로, 목록은 계속 거부합니다. 실제 공개 링크 검사 근거: public-link-results.json.
